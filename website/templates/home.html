Know what your agents do.
Decide what they may do.

nandi sits between AI agents and the LLM APIs, MCP servers and other agents they talk to. It records every call, checks it against your policy before it runs, and holds the risky ones for a person to approve. One static binary, about 20 MB of memory.

What it catches

Each of these is a scenario in the evaluation corpus that runs in CI on every change, modelled on published attacks against agents.

Injected instructions that move money or data

An invoice tells the agent to pay a new IBAN. The IBAN appeared only in the invoice, never in what the user asked, so the payment is held for approval.

taint.flow

Tools that change after you trusted them

Tool definitions are pinned the first time a server lists them. A description rewritten later is flagged and the tool is blocked until someone reviews it.

tool.drift

Poisoned and shadowing tool descriptions

Hidden instructions, requests to read ~/.ssh, smuggling parameters, and descriptions that try to change how another server's tools behave.

tool.poisoning.*, tool.shadowing

Secrets and canaries on their way out

47 credential formats, PII with checksum validation and your own honeytokens, including when wrapped in base64, hex or URL encoding.

secret.*, honeytoken

Requests for cloud credentials

Metadata endpoints, private ranges and encoded loopback addresses in tool arguments, without blocking a coding agent's own localhost dev server.

ssrf.metadata

Effects nobody declared

On Linux the host sensor watches the agent's process tree. A curl or a credential read with no matching tool call stands out.

sensor.undeclared-exec

Where it sits

A proxy for SDKs, a wrapper for stdio MCP servers and hooks for coding agents. They share sessions, so what one sees informs what the others allow.

Policy you can read

Argument rules and sequences in YAML, who-may-do-what in Cedar. Start in monitor mode, replay recorded traffic against a new policy, then enforce.

policies/rules.yaml

rules:
  - id: large-payment
    match:
      tool: "*pay*"
      args: { amount: { gt: 1000 } }
    action: ask
sequences:
  - id: refund-needs-verification
    tool: "*refund*"
    requires_prior:
      tool: "*verify_identity*"
      same_args: [user_id]
    action: deny

policies/policy.cedar

@id("interns-no-repo-delete")
forbid (
  principal in Group::"interns",
  action == Action::"call_tool",
  resource == Tool::"github/delete_repository"
);

@id("merge-needs-approval")
@action("ask")
forbid (principal, action,
  resource == Tool::"github/merge_pull_request");

Small enough to run everywhere

One process per laptop, per pod or in front of a fleet. Nothing in the request path calls a model.

Binary16 to 20 MBstatically linked, no runtime dependencies

Evaluation corpus41 / 41attack checks caught, 0 false positives in 36 benign checks. The corpus is ours; treat it as a regression suite, not a benchmark.

Built on published research

Most features come from a paper or an existing product. The research page maps each one.

  • CaMeL: Defeating Prompt Injections by DesignUntrusted data must not drive consequential actions. Became taint tracking.
  • FIDES: Securing AI Agents with Information-Flow ControlIntegrity labels on tool output. Became the session taint label.
  • Progent: Programmable Privilege ControlArgument-level tool policies. Became the YAML rule language.
  • ETDI: Enhanced Tool Definition InterfaceImmutable, verifiable tool definitions. Became tool pinning.
  • Pro2GuardProbability of reaching an unsafe state. Became the behaviour lookahead.
  • AgentSighteBPF boundary tracing for agents. Became the host sensor.
